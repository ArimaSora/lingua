# MVP 范围：单用户、中英语言对、端到端薄闭环、本地常驻 Web Chat

MVP 的边界一次定死：(1) 只服务开发者本人，零账户零多租户，但学习日志 schema 预留 user_id；(2) 语言对中文→英语，语言对做成配置项但第一版只调通中英；(3) 内容管道与角色聊天**两条线都做最薄版并端到端打通**——RSS 订阅（含带文字稿的音频 RSS）/ 粘贴链接 → 提取语块 → 预学 → 角色聊天埋伏 → 传感器判分入库，因为产品的核心赌注是闭环本身而非任何单线（RSS 进 MVP 的决定见 ADR-0008，替代原「RSS 后置」方案）；(4) 本地常驻进程 + 自建极简 Web Chat 单渠道，Telegram/QQ/移动端后置（**不设渠道抽象层**：Web Chat 直连 agent loop，第二个渠道出现时再提取接缝，见 ADR-0017）；(5) LLM 用 DeepSeek 主模型 + Qwen-flash 级传感器（OpenAI 兼容 API，可换），第一版不碰本地模型。

## Consequences

- 「两条薄线端到端」是对「先做一条线」的刻意偏离：端到端闭环无行业先例数据，MVP 的使命是验证闭环而非验证组件。
- 首日埋点四个指标：埋伏命中率、话题回应率、语块掌握曲线、留存。
- 冷启动不做定级测试：用户从零开始，初始按 A1 处理，定级锚直接由行为数据（FSRS/PFA）建立；cloze 定级器暂缓实现，保留为有基础用户的可选功能。
- 角色人格 = 模板基底 + 订阅源推断兴趣层，存 curated facts。
