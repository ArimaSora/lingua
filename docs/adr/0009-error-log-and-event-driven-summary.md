# 错误流独立于记忆：事件驱动的系统小结

AfterTurn 阶段分两条流：(1) 语块判分（规则命中 + 判分模型判用法正误）进入学习者状态（FSRS/PFA），这条不变；(2) 语法错误写入独立的错误日志——不入关系记忆、不注入 prompt、不直接进 FSRS——由系统消费。系统小结为**事件驱动**：检测到话题结束或错误累计 ≥3 条时，在系统会话发送该话题的小结（prompt 式留白纠错）；不设每日汇总，仅保留小结内的「明日到期预告」。依据：每日一次的频率不够及时（用户决策）；小结放在系统自己的会话里，想看才看，不打断与角色的对话心流（保护心流的依据见 ADR-0008）。

## 话题边界启发式

「话题结束」没有显式信号，用启发式近似：**30 分钟无活动即视为话题结束**（`@lingua/core` 的 `TOPIC_IDLE_MS`，埋伏式复习话题 opened_at 起算；已 resolved/stale 的话题天然视为结束）。30 分钟取自一次自然对话往返的耐心上限——学习者不是已离开（去忙别的），就是本轮练习已经收尾；两种情形都适合补一条不打扰的小结。这是可调参数而非承诺：阈值变动不需要新迁移，改常量即可。

## Consequences

- 错误日志同时为「角色眼中的你」抽检页供数。
- 用户长久不看系统会话时，错误洞察会闲置——接受此风险，强迫查看会破坏系统/角色的职责分离。
- 30 分钟启发式会偶发误判（如学习者 29 分钟后回来继续同一话题）——接受：多收一条小结的代价远小于在角色会话里打断心流。
