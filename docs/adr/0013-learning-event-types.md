# 学习事件：二维观测 × 确定性派生规则

观测拆为两个维度，判分器（规则 + 判分模型）只负责提供证据；事件派生与状态更新映射由 lingua-core 领域逻辑执行（确定性、可单测）：

- **辅助情况**：无辅助 / 有辅助（近 N 轮内角色或系统示范过该语块形式，或用户先求助）
- **产出结果**：正确 / 错误 / 未产出

事件更新矩阵：

| 辅助 | 结果 | 事件 | FSRS | PFA |
|---|---|---|---|---|
| 无 | 正确 | 独立产出 | Good | 成功 |
| 无 | 错误 | 独立尝试失败 | Again | 失败 |
| 有 | 正确 | 辅助产出 | 不更新 | 不更新 |
| 有 | 错误 | 辅助尝试失败 | 不更新 | 失败 |
| — | 未产出 | 未获得证据 | 不更新 | 不更新 |

v1 规则：独立正确统一映射 Good，**Easy 不自动产生**（后续可由延迟复现抽查引入）；辅助×失败只记 PFA 不记 FSRS——记忆状态的证据要求无辅助条件，技能层面的困难如实记录；未产出仅计埋伏命中率，永不记失败。阅读侧：查词 = 未知信号；认出 = 弱信号，不入 FSRS。

配套硬规则：**话题生成器不得在提示中包含目标语块的形式或直译**——否则命中永远无法与复述区分。

依据：测试效应要求提取发生在无提示条件下（Karpicke & Roediger 2008）；未命中不代表不会（替代正确表达同样达成交际目标）。

## Consequences

- 埋伏命中率 = 独立产出 / 埋伏次数。
- 判分 prompt 需携带「近期是否暴露该语块」的上下文标记；判分器输出两维度证据而非事件结论。

## 实现状态（2026-10-04，issue #18）

「用户先求助」检测口径已落地（v1）：确定性显式标记词（`packages/lingua-core/src/ambush.ts` 的 `HELP_REQUEST_RES`）——用户消息中出现求助标记，且标记起点早于该语块命中起点（命中位置复用判分管道的确定性匹配），该语块判对时计辅助（assisted）。LLM 分类口径留待验证协议的人工标注样本（docs/validation.md）证明需要时再引入。

口径限定：话题在首个用户回合结算（单回合话题模型），故「先求助」检测限定在本回合用户消息内——跨回合的「上一轮求助、本轮产出」不计辅助。另：求助信号（`askedFirst`）是用户侧辅助信号，与暴露证据（`exposedRecently`）分开计算——后者才注入判分 prompt（「近期是否暴露」指角色/系统示范，求助不构成示范）。
