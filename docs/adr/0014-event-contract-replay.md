# 事件契约与重放语义

评分日志为 append-only 事件流。每个事件至少包含：event_id（ULID）、**observation_id**（稳定观测标识：同一用户消息的同一次观测，重试共享）、occurred_at 与 recorded_at、话题/会话指针、原始观测引用（用户消息原文、判分输入输出原文）、事件类型（ADR-0013）、置信度、判分器与版本、params_version（指向冻结的参数快照表，不内嵌参数）、applied（**当时**是否参与状态更新，纯审计字段）、voids / superseded_by 指针。

规则：

1. **原始观测永不删除**：低置信度判分保留原文与结果。
2. **同一 observation_id 的多次判分构成版本链**；更换判分器重新评估 = 在同一 observation 下追加新版本，与新增练习天然区分。
3. **纠错 = 追加撤销/替代事件**，不修改原记录。
4. 事件排序按 (occurred_at, event_id)；撤销/替代事件以 recorded_at 进入时间线。
5. **有效观测解析（统一管线，所有状态投影必须经过）**：时间截点 → 每个 observation 解析有效版本（截至查询的知识地平线，最新且未被撤销的版本；只取该版本，低置信度**不回溯**旧版本）→ 置信度阈值 + 事件矩阵（ADR-0013）准入筛选 → 状态投影。`applied` 只是「当时实际是否更新」的审计记录；**投影资格仅由本管线推导，原始观测的存在本身从不授予更新资格**——低置信度观测在重放后仍不影响状态，除非同一 observation 出现新的合格判定。
6. **as-of 双模式**（知识地平线必须显式给定，防未来信息泄漏）：当时所知 = 只考虑 recorded_at ≤ T 的事件与撤销记录，按当时参数版本投影；当前认知 = occurred_at ≤ T、排除任何时间被撤销者，按当前参数版本投影。两种查询都必须可答。

## Consequences

- **写入接口收窄**：生产者只调 `recordEvidence(observation_id, 语块引用, 辅助情况×产出结果, 置信度, 原文引用)`；事件类型、applied、矩阵映射全部由存储追加路径派生——写入者永远碰不到 applied，事件构造规则只有一个家。
- 「角色眼中的你」抽检页的每次纠正生成替代事件，状态重算自动发生。
- 事件流即审计链：任何时刻的学习者状态（当时所知 / 当前认知）都可解释、可质疑。
- 验收用例：低置信度观测重放后仍不影响状态；同一观测被纠正后，历史查询不泄漏未来信息、不重复计数。
