# 接缝清点：真接缝白名单与假想接缝拒绝

开工前对设计做接缝清点（判据：一个适配器 = 假想接缝，两个以上 = 真接缝）：

**真接缝（保留）**：
- Judge 接口（判分证据）：Jev / Qwen-flash 级 LLM / 测试 fake，三个适配器。
- 时钟端口：真实时钟 / 假时钟（重放、调度、「隔日复现」测试的硬依赖）；ID 生成并入此端口，不单独开缝。
- 事件存储 fixture 注入口：唯一允许的**内部测试接缝**，其余测试一律经 lingua-core 包边界（replace, don't layer——包边界测试覆盖到某行为时删除对应内部测试）。

**假想接缝（删除/不建）**：
- 渠道抽象层：MVP 只有 Web Chat 一个适配器，直连 agent loop；Telegram/QQ 出现时再提取接缝（修订 ADR-0007 的「从第一天可插拔」）。
- LLM provider 端口：Vercel AI SDK 已是这一层，OpenAI 兼容配置项足够，不重复抽象。

**模块形状约定**：digest 模块收拢选料 + token 预算 + 渲染（对外 `renderDigest` 一个函数，内部三段：埋伏目标/近期弱点/角色须知——与讲解的「三层解释」命名区分开）；难度管道对外只暴露 `assess(content) → (难度级, 覆盖率, 时效标签)`，L1/L2/L3 三层是实现细节；调度器单一模块（推送 tick），入账改为查询时惰性结算，消除第二个 tick。
