# Lingua MVP 规格

- 日期：2026-10-03
- 依据：docs/research/ 七份研究报告、GLOSSARY.md、docs/adr/0001–0012
- 术语：一律使用 GLOSSARY.md 词汇

## Problem Statement

作为中文母语、从零开始的英语学习者，我面对的现状是：背单词本质上是无趣的打卡，坚持不下来；AI 生成的学习文章我不爱读；真实感兴趣的内容（agent 领域的 RSS、文章）又远远超出我的水平。我想要的不是又一个课程软件，而是一个能住进我订阅流和日常聊天里的学习环境——读我想读的，聊我想聊的，复习在我没察觉的时候发生。

## Solution

一个本地常驻的个人语言学习 agent，IM 界面里有两个联系人：

- **系统**：管理我的 RSS 订阅（含带文字稿的音频），推送内容时自带预学（可展开语块清单），为零基础的我按序推送 Bootstrap 课包，话题结束后把学习性纠错以小结形式发在它自己的会话里。
- **好友角色**：一个和我兴趣对齐的英语朋友，网聊风格短回复，主动起话题时自然埋入我快到期的语块（埋伏式复习），只在影响理解时当场澄清，从不给我上课。

学习以语块为单位；我的掌握状态全部由行为数据计算（ts-fsrs + PFA），不靠 LLM 记忆；语言讲解由结构化知识条目约束，默认只给"例句+一句直觉规律"，深挖由我触发。

## User Stories

**订阅与内容**

1. 作为学习者，我希望订阅 RSS 源（含带文字稿的音频播客），以便学习内容来自我的真实兴趣。
2. 作为学习者，我希望把自己找到的 RSS 源添加进订阅，以便内容库随我的兴趣生长。
3. 作为学习者，我希望粘贴一个链接给系统就能纳入学习流，以便偶发看到的好文章不被订阅源形式限制。
4. 作为学习者，我希望系统推送新内容时告诉我"为什么你会感兴趣"，以便我决定要不要点开。
5. 作为学习者，我希望推送自带可展开的语块清单（每条只有例句+一句直觉规律），以便三分钟完成预学再读原文。
6. 作为学习者，我希望带文字稿的音频能边听边看文字稿，以便同时练听力和阅读。
7. 作为学习者，我希望太难的文章不直接砸给我，以便我不被挫败感劝退。
8. 作为学习者，我希望太难的常青内容进解锁队列并标注"约什么级别解锁"，以便难度差变成看得见的进度钩子。
9. 作为学习者，我希望太难的时效性内容（agent 新闻）立刻给我简化版（标注"简化版"并附原文链接），以便信息不过时。
10. 作为学习者，我希望角色会用大白话跟我聊我订的难文章讲了什么，以便我现在就能参与话题讨论。

**Bootstrap（零基础）**

11. 作为零基础学习者，我希望系统按序推送入门课包（高频生存语块、基础句构、A1 分级短文），以便我不面对野生内容无从下手。
12. 作为学习者，我希望课包内容也走"推送→预学→角色埋伏使用"的闭环，以便入门材料和真实内容享受同一套复习机制。
13. 作为学习者，我希望不做入学定级考试，直接从头开始，以便第一天就有体验而非先被测一遍。

**角色与对话**

14. 作为学习者，我希望有一个和我兴趣相同的朋友角色，以便聊天本身有吸引力。
15. 作为学习者，我希望角色用网聊风格短回复，以便对话轻松无压力。
16. 作为学习者，我希望角色的消息附可展开的中文翻译，以便我读不懂时随时有脚手架。
17. 作为学习者，我希望角色主动起话题找我聊，以便学习由"被想起"驱动而非靠我的意志力。
18. 作为学习者，我希望角色起的话题里自然藏着我要复习的表达，以便复习在我不察觉时发生。
19. 作为学习者，我希望角色只在我表达影响理解时才当场澄清，以便对话心流不被纠错打断。
20. 作为学习者，我希望角色懂中文但平时不跟我说中文，以便我没有逃避输出的永久逃生舱。
21. 作为学习者，我希望卡住时能直接用中文求助并得到救场，以便极端情况下对话不崩。
22. 作为学习者，我希望随着水平提高角色越来越少用中文救场，以便我的输出被渐进拉长。
23. 作为学习者，我希望偶尔被角色拉进场景剧本（如模拟打电话），以便我接触闲聊之外的语域。
24. 作为学习者，我希望角色讲某个表达时标注语域（"这句很口语"），以便我建立语域意识。
25. 作为学习者，我希望角色记得我是谁、我喜欢什么、我们聊过什么，以便关系有连续性。

**复习与纠错**

26. 作为学习者，我希望学习性纠错过后以小结形式出现在系统会话，以便纠错不打断我和角色的关系。
27. 作为学习者，我希望小结里的纠错是留白式的（给现象让我自己想，点开看答案），以便纠错本身也是提取练习。
28. 作为学习者，我希望系统小结里告诉我明天有多少到期内容，以便我有预期。
29. 作为学习者，我希望不做翻卡打卡，以便复习不靠自律。
30. 作为学习者，我希望在"角色眼中的你"页面看到系统判分记录并能纠正误判，以便我的学习数据可信。

**讲解**

31. 作为学习者，我希望问"这个表达怎么回事"时得到例句+一句直觉规律，以便十秒内回到内容。
32. 作为学习者，我希望我想深挖时能展开到术语和理论，以便满足偶尔的好奇心。
33. 作为学习者，我希望讲解包含中英思维差异（如"英语把动作挂在主语上"），以便获得"原来如此"的兴奋感。
34. 作为学习者，我希望讲解内容有依据而非 AI 现编，以便我信任它。

**状态与反馈**

35. 作为学习者，我希望看到今日到期数量，以便心里有数。
36. 作为学习者，我希望看到自己的掌握度随时间变化，以便获得进展感。
37. 作为学习者，我希望点击查词的行为被记住（LingQ 式状态），以便阅读数据也参与调度。

## Implementation Decisions

**架构（ADR-0001/0007）**

- 单一仓库：`lingua-core` 框架无关纯领域包 + 薄壳（agent loop、渠道、适配器）。全部 IO（LLM、判分、RSS、渠道）为可替换适配器。
- 本地常驻单进程；渠道层可插拔，MVP 仅自建 Web Chat；Telegram/QQ/移动端后置。
- 存储：本地 SQLite 单文件 + 定时备份（备份=复制文件）；MVP 不加向量层。

**模型分工（ADR-0010）**

- 主模型 DeepSeek：角色对话、讲解、话题生成、LLM 改写。
- 判分：Judge 接口。语块命中判定 = 确定性规则（词形还原 + 字符串匹配）；用法正误 = Jev（校准置信度，低于阈值丢弃）。Jev 早期访问不可用时降级 Qwen-flash 级 LLM 判分，配置级切换。
- 轻量任务（记忆门控、错误归并）：混元 lite（搭建时实测 TokenHub 可用性，失败换 Qwen-flash）。
- 全部模型走 OpenAI 兼容配置项；Jev 单独适配器。

**学习者状态（ADR-0002/0006）**

- 语块级记忆状态：ts-fsrs。技能点级掌握度：PFA（不用 BKT/DKT）。辅以 LingQ 式查词状态与输入时长。
- 评分日志 append-only 可重放；抽检纠错 = 标记无效 + 重放重算。
- 初始等级 A1（不做定级测试），行为数据接管。
- 对话 prompt 只注入 ≤300 token 的三层 digest：本轮埋伏目标（到期语块）+ 近期弱点（PFA 最低技能点）+ 角色须知（相关 curated facts）。

**双联系人与主动性（ADR-0008/0009）**

- 系统联系人：订阅管理、推送（自带预学）、Bootstrap 课包、事件驱动小结（话题结束或错误 ≥3 条触发，prompt 式留白纠错 + 明日到期预告）、错误日志消费。纯工具文案无人格。
- 角色联系人：闲聊、分享讨论订阅内容、埋伏式复习、影响理解时的澄清式询问。每日 1–3 次主动起话题为基线，候选池 = 到期语块 + 订阅新内容，事件驱动有料才起；每话题埋 2–4 个到期语块，同语块 48h 内最多埋 2 次，未命中回炉重排。
- 纠错分工：角色只做影响理解的当场澄清；一切学习性纠错归系统小结。

**语块与内容管道（ADR-0012）**

- 语块提取：轻量模型提取候选并标注 CEFR 等级与类型（搭配/惯用语/句构）；每篇入选 8–12 个，筛选 = 理解本文必需 + i+1；已在 FSRS 库中的语块优先（制造复现）。
- 难度评估三层管道：L1 CEFR 词表累计覆盖率（EFLLex，CC BY-NC-SA；解锁级 = 首个覆盖率达 95% 的级别；词形还原复用判分管道）+ L2 平均句长约束 + L3 LLM 粗评三档交叉验证（不单独定级）。
- 时效分流：易腐 + 太难 → LLM 改写版（标"简化版"附原文链接）或角色转述，不进解锁队列；常青 + 太难 → 解锁队列；队列中易腐条目过期清理。
- 音频：带文字稿 → 文字稿进管道，内嵌极简播放器；无文字稿后置。

**双语与语域（ADR-0004/0005/0011）**

- 母语支架四档：A1–A2 救场无限制 + 角色消息附可展开中文翻译；B1 仅明确求助时救场；B2 澄清请求代替救场；C1+ 全目标语。用户可手动临时下调一档，系统记档不评判。
- 讲解：知识条目约束（首批手工种子 30 条：中英思维差异 10 / 高频语法 10 / 语用语域 10，AI 起草 + 一手来源校验 + 证据等级字段）；三层呈现（例句 → 直觉规律 → 术语），默认第一层。语言思维用 thinking for speaking 框架；"形合/意合"标注为教学性概括。
- 语域：角色消息语域标注；场景剧本与转述承载语域多样性；CEFR 社会语言得体性量表做解锁分级。
- 角色定义：角色卡（人格基底模板 + 订阅源推断兴趣层 + Lingua 扩展字段：母语支架档位、语域范围、语言对），存 curated facts。

**数据 schema（决策级，非 SQL）**

- 表：语块（文本、类型、CEFR、来源内容 ID）、评分日志（append-only：语块 ID、判定、置信度、上下文指针、无效标记）、技能点掌握（PFA 参数）、错误日志（原文、错误类型、话题指针）、内容条目（来源、难度分、时效标签、解锁级、状态）、订阅源、角色卡、关系事实、指标事件（埋伏命中、话题回应、留存）、学习者档案（当前 CEFR 自评锚、支架档位、语言对配置）。
- 全部按语言隔离；预留 user_id。

**度量（首日埋点）**

- 埋伏命中率、话题回应率、语块掌握曲线、留存。
- 验证约定：4 周自测；话题回应率 ≥50%、命中率 <30% 先调话题生成；看什么数据调什么旋钮（操作手册：docs/validation.md）。

## Testing Decisions

- 唯一接缝 = `lingua-core` 包边界；测试只测外部行为，不测实现细节；所有 LLM/判分/RSS/渠道适配器在测试中用 fake。
- 必测模块：FSRS 调度集成（到期队列排序、回炉重排）、PFA 更新（用 Pavlik 论文示例值校验）、难度管道（固定文本样本的覆盖率/解锁级）、digest 渲染（长度上限与三层内容）、埋伏调度器（候选池 → 话题选择的规则）、评分日志重放（纠错后状态正确重算）、解锁队列状态机（含易腐条目过期）。
- 先例：绿地项目无既有测试先例——本规格建立约定：每个领域模块一个测试文件，fixture 驱动，禁止在测试中发起真实 LLM 调用。

## Out of Scope

- v0.2：窄推送、电量模型自适应轮询、Telegram/QQ、语音、视频字幕、RAG 知识库基础设施、向量层（sqlite-vec）、角色卡导入兼容。
- v0.3：日语（专属角色、假名课包与罗马字标注渐退）。
- 多用户/账户体系、移动端、本地模型、设置页与统计图表 UI、周维度报告。

## 修订记录（2026-10-03 设计审查）

六条审查结论全部接受，裁决细节见 ADR-0013/0014/0015。本节与上文冲突时以此节为准。

1. **学习事件类型**（ADR-0013）取代"判分 = 二元对错"：独立产出 / 辅助产出 / 尝试失败 / 未产出（= 未获得证据，永不记失败）；话题生成器不得在提示中包含目标语块形式或直译。
2. **事件契约**（ADR-0014）取代数据 schema 中的评分日志字段：原始观测永不删除、低置信度仅 applied=false、纠错 = 追加替代事件、重放分 reproduce / recompute 两模式。
3. **三旋钮分离**（ADR-0015）取代"初始 A1，行为数据接管"：内容难度偏好由个性化覆盖率驱动；母语支架档位用户可控、系统建议需确认；CEFR 仅展示与手动设置，自动升级暂缓。
4. **准入控制**：候选语块（提取即入池，零成本）与正式语块（进 FSRS 调度）分离；每日新增上限按近 7 天实际完成量自适应；到期积压超阈值暂停新增；RSS 更新不自动成为学习任务。
5. **语块身份**：v1 仅支持搭配与惯用语两类；语块实体（规范形式 + 允许变体 + 槽位模式如 `look ___ up`）与其在内容中的出现记录分离；无法可靠匹配的类型不判失败，仅记观察机会。
6. **验证协议补充**：建 50–100 条人工标注真实对话样本校验判分器（工程测试照留）；4 周自测加入"隔数日、换语境、无提示"的复现抽查（由角色自然执行，非考试）。

新增用户故事：

38. 作为学习者，我希望没用到目标表达不会被误判为"没学会"，以便我的状态不被话题设计质量牵连。
39. 作为学习者，我希望能看到系统认定我掌握某语块的依据链，以便状态可解释、可质疑。
40. 作为学习者，我希望积压时系统减少新任务而非堆债，以便学习节奏可持续。

测试接缝表述修正：主接缝为 `lingua-core` 包边界；内部模块允许拥有自己的可测试接口。

**施工起点（第一条 tracer bullet）**：一份 Bootstrap 内容 → 少量语块预学 → 角色诱发产出 → 可解释的事件记录 → 状态更新 → 隔日再次使用。RSS 保留最薄入口；自动 CEFR 升级、完整解锁队列、复杂语域机制等闭环数据可信后再展开。

### 第二轮修订（2026-10-03 复审）

- 事件更新矩阵与二维观测模型落入 ADR-0013：判分器供证据（辅助情况 × 产出结果），领域逻辑执行映射；Easy 不自动产生；辅助×失败只记 PFA。
- 冷启动路径与准入控制落入 ADR-0016：首周种子额度每日 5 个正式语块；`initial-learning` 事件不冒充成功回忆；首次到期 = 预学次日。
- 个性化覆盖率口径、双覆盖数展示、「原文难度约 B1」措辞落入 ADR-0015；冷启动期个性化层不启用。
- 重放去重 / 排序 / as-of 语义落入 ADR-0014：observation_id 版本链区分重估与新增练习；「当时所知」与「当前认知」两种投影都必须可答。
- ADR-0004（支架触发）、0005（三层定义）、0010（低置信度处置）已标注被 ADR-0013/0014/0015 修订。

### 第三轮修订（2026-10-03 三审）

- ADR-0014 增加统一的**有效观测解析管线**（时间截点 → 有效版本 → 置信度与矩阵准入 → 状态投影）；applied 降级为纯审计字段，原始观测的存在从不授予更新资格；as-of 查询必须显式给定知识地平线。
- ADR-0016 改为**额度账户制**：种子期退出条件依据有效学习历史（累计复习 ≥20 且活跃 ≥3 天）；自适应期保底每日入账 1，余额累积解决小数与低频问题；积压只暂停不扣减。
- 四条场景固化为验收用例，阻塞相关实现：(1) 低置信度观测重放后仍不影响状态，除非有新的合格判定；(2) 同一观测被纠正后，历史查询不泄漏未来信息、不重复计数；(3) 首周未学习的用户第 8 天仍能启动第一条闭环；(4) 低频学习者的新增额度明确、可持续。

### 第四轮修订（2026-10-03 深模块审查）

- **事件管线不再分票**：整条有效观测解析管线（含矩阵准入）归票 01，对外只暴露 as-of 双模式投影查询；事件写入收窄为 `recordEvidence`（ADR-0014），写入者不碰 applied。
- **接缝清点**（ADR-0017）：删渠道抽象层与自建 LLM provider 端口；真接缝白名单 = Judge / 时钟端口（含 ID）/ 事件存储注入口；内部测试接缝只此一个，其余经包边界。
- digest 改三段式并收拢选料+预算+渲染；难度管道对外仅 `assess(content)`；调度器单一模块，入账改惰性结算。
- 票 05（Web Chat 壳）为集成票，手工/e2e 验收；带规则的部分（角色卡→digest 输入、翻译折叠档位）必须下沉 lingua-core。

### 实现映射补记（issue #20，2026-10-04）

第二轮 code-review（spec 轴）发现票 04/05 的部分验收语句在实现中选择了等效但不同的落点。逐条映射如下；凡实现与 spec 字面有偏差的，已将等效实现写回本 spec（保持「spec 是唯一事实源」）。
